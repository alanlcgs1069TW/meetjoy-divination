# 紫微斗數命盤 — 說明書

純前端的紫微斗數排盤網頁。排盤運算全在瀏覽器完成，
**命盤資料不經任何伺服器**；登入只用於跨裝置同步，不登入也能完整使用。

---

## 〇、給接手的人（以及你請來幫忙的 AI）

先讀這一節再動手，可以省掉大量白工。

### 這個專案可以完全離線自足

**不需要 Supabase、不需要 Cloudflare、不需要任何雲端帳號**，就能跑完整功能。
已實測：把環境變數全部拿掉後，排盤、存盤、十二宮、四化、大限流年、進階模式
全部正常，只有 console 會印一行 `[Supabase] Missing env vars`。

- 後端（Supabase）**只影響登入與跨裝置同步**，其餘功能完全不依賴它
- Cloudflare **只是原作者選的部署平台**，包裡沒有任何 Cloudflare 專屬檔案
  （沒有 `wrangler.toml` / `_headers` / `_redirects` / `functions/`）。
  `npm run build` 出來是純靜態 `dist/`，放哪裡都行，或根本不部署

所以第一步不要去設定雲端服務，先把它跑起來看到盤，再決定要不要接後端。

### ⛔ 以下這些「看起來像 bug」的東西，是對的，不要修

這個專案依**特定學會的教法**實作，與坊間常見版本刻意不同。
AI 特別容易「好心修正」以下幾點，改了就是把正確的東西改壞，而且**不會有任何報錯**：

| 現象 | 為什麼是對的 |
|---|---|
| 大限與小限的歲數**差 1** | 大限看實歲、小限看虛歲，這是定義 |
| 十干四化表與網路上查到的不同 | 依學會版，見 `claude.md` §4。**這張表不可更動** |
| 大限沒有「限馬」、流年沒有「年馬」 | 學會版就是沒有 |
| 晚子時排盤用隔日，但顯示的生日是當天 | 排盤規則 vs 實際日期，兩者本來就該不同 |
| 天馬用「節氣月」而非「農曆月」 | 曾為此錯過三次，見 `GOTCHAS.md` |
| 查表陣列的數值與某些教材對不上 | 多數已逐格驗證過，見 `FORMULAS.md` |

**要改任何查表陣列、起點或方向之前，先讀 `GOTCHAS.md`。**
那份檔案記的全是踩過的坑與當初的判斷依據，很多條目就是在講「這個看起來錯，但其實是對的」。

### 沒有自動化測試可以接住你

交付包不含測試與驗證腳本（原本的驗證資料是真人命盤，依隱私要求移除）。
改算法沒有安全網，建議自己先建幾張有把握的基準盤，改完逐宮比對。
詳見 §四-3。

### 既有的 lint error 不是你弄壞的

`npm run lint` 開箱就有 13 個 error，全是既有狀況，不影響建置與執行。
詳見 §五。不要花時間以為是自己造成的。

## 一、跑起來

```bash
docker compose --profile test up -d     # → http://localhost:5174
```

`--profile test` 不能省。詳細與非 Docker 的做法見 `SETUP.md`。

不需要任何帳號或金鑰就能排盤、存盤（存在瀏覽器 localStorage）。

### 要用登入／跨裝置同步的話，你得自己開一個 Supabase 專案

這個交付包**不含任何後端帳號或金鑰**。原作者的 Supabase 專案不會、也不該給你用
（裡面是他自己與客戶的命盤資料）。所以：

- **不做任何設定** → 排盤、存盤、編輯、分類、進階模式全部可用，資料存在瀏覽器裡。
  單機使用完全夠，可以先這樣跑一陣子。
- **要登入與跨裝置同步** → 到 [supabase.com](https://supabase.com) 開一個免費專案，
  照 `SETUP.md` §2 填 `.env.local`、建兩張表、開啟 Email 登入。大約十分鐘。

沒設定時登入會失敗，瀏覽器 console 也會看到
`[Supabase] Missing env vars` 的提示（`src/lib/supabase.ts` 會退回佔位網址）。
**這是預期行為，不是壞掉** —— 排盤本身完全不受影響。

## 二、功能導覽

### 命盤資料庫（首頁）
- 新增／編輯／刪除命盤，可加分類標籤（內建五種 + 自訂上限 7 個）
- 搜尋姓名或日期
- 右上鎖頭 = 隱藏模式：姓名換成代號，方便截圖時不露出當事人

### 命盤頁
- **本命盤**：十二宮、主星輔星雜曜、四化、長生十二神、博士十二神、大限與小限年齡
- **大限／流年**：下方兩條時間軸點選；再點一次目前那格可取消
- 命主目前所在的大限，年齡範圍會標紅
- **中央資訊卡**：姓名、時辰（左右箭頭可微調定盤）、陰陽男女、五行局、國曆／農曆生日

### 進階模式（中央卡「進階」鈕）
多出流月／流日／流時三層與底部導航列。

- **斗君鏈**：流月命宮由斗君法定出 → 流日 = 流月 +（農曆日−1）→ 流時 = 流日 + 時辰序
- **焦點視窗**：一次只顯示「焦點層 + 往上兩層」共三層運線，不會全疊上去糊成一片
- **底部導航列** `🕐 | 流月 | 流日 | 流時`
  - 點**名稱**（如「六月」）= 只切焦點
  - 點**干支**（如「乙未/丙申」）= 開選單換一個
  - `◀ ▶` = 前後移動一格
  - `🕐` = 日期／時辰選擇器，可直接用國曆日期跳轉

### 飛化與自化
- **飛化上色**：點任一宮，以該宮宮干四化，替落在他宮的目標星上色
- **自化箭頭**：離心（自化出）貼宮格外緣朝外、向心（自化入）朝盤心
- 四化配色：祿綠／權紫／科藍／忌紅，集中在 `src/lib/huaColors.ts`
- **立太極**：點宮後各宮加一列「◯之△」

### 語言
介面支援三種：**繁體中文 / 简体中文 / English**（側邊欄「語言」切換）。
另有獨立的**拼音**開關（中央資訊卡的 `Pinyin` 鈕）。

桌機中英並陳；手機（≤768px）空間不足，改為中文／拼音二選一。

> **簡體字典有 5 個已知缺口**：`src/i18n/index.ts` 的條目只在簡繁有差異時才加
> `'zh-CN'` 欄位（146 條中有 51 條），設計上正確；但 `歲建`、`喪門`、`歲驛`、
> `化祿`、`化權` 這 5 條含繁體專用字卻漏了該欄位，簡體模式下會顯示繁體字形。
> 補上即可，字典內容請比照現有格式。

## 三、專案結構

```
src/
  lib/engine/native/    排盤引擎 —— 農曆換算、命宮、主星、輔星、雜曜、流曜
  lib/astrolabe/        組盤與運限 —— 大限、小限、雙胞胎盤、運限過濾
  lib/huaColors.ts      四化配色（三處共用，勿各自複製）
  components/           UI；AstrolabeChart 是盤面主體，PalaceCell 是單一宮格
  i18n/                 中英／拼音字典與宮位名稱
  contexts/             語言狀態
```

改**排版**看 `components/`，改**算法**看 `lib/`，兩者不要混著改。

## 四、動手前務必先看

### 1. 客製化邏輯不可隨意更動
`claude.md` §4 列了十干四化表與計算規則，依**學會教法**定，與坊間部分流派不同，不是 bug：

- **大限看實歲、小限看虛歲**，兩者差 1 是定義
- **晚子時**（23:00–24:00）排盤時視為隔日，但顯示的生日仍是當天
- 大限只有限祿／限羊／限陀，**沒有限馬**；流年沒有年馬

### 2. 已知陷阱
`GOTCHAS.md` 記了每個踩過的坑與判斷依據 —— 長生十二神方向、博士十二神起點、
天馬用節氣月而非農曆月、閏月命宮、雙胞胎盤順逆偵測等。
**改算法前先搜尋這個檔**，很多「看起來像 bug」的其實是正確的。

### 3. 沒有自動化測試 —— 這是本專案最大的缺口
交付包**不含任何測試或驗證腳本**（原本的驗證資料是真人命例，已依隱私要求移除）。
`FORMULAS.md` 記錄了每條公式的來源與推導，但**沒有可執行的回歸測試**。

實務建議：改任何查表陣列、起點或方向之前，先自己建立幾張你**有把握的命盤**當基準，
改完逐宮比對。`FORMULAS.md` 的公式說明足以讓你判斷結果對不對。

### 4. 開發歷程
`CHANGELOG.md` 依日期記錄每次改動**以及為什麼這樣改**，包含被否決的方案與理由。
要理解某段程式為何長這樣，先查這裡。

## 五、已知的既有問題

接手前先知道，免得以為是自己弄壞的：

- `npm run lint` 開箱有 **13 個 error**（未使用變數、`any`、全形空白混進 JSX 等），
  皆為既有狀況，不影響建置與執行
- `tsconfig.app.json` **沒有開 `strict`**。實測開啟後是 0 error，建議接手後就打開
- `dist` 是單一 chunk 約 800 KB（gzip 250 KB），未做 code splitting，build 會有警告
- `.npmrc` 設了 `legacy-peer-deps=true`，升級套件時注意被隱藏的相依衝突
- 版本戳記（Sidebar 右下）由 build 時的 `git rev-parse` 產生。本包不含 git 歷史，
  所以第一次 build 會看到 `fatal: not a git repository`，版本顯示為 `dev`。
  **不影響功能**，接手後自己 `git init` 即可恢復

## 六、資料與隱私

- 命盤預設只存在瀏覽器 localStorage，**不設定後端也能完整使用**
- 雲端同步需要你自己的 Supabase 專案（見 `SETUP.md` §2）；採 Row Level Security，每位使用者只讀得到自己的資料
- 同步為 last-write-wins（比較 `updatedAt`），刪除是軟刪除
- 隱私政策頁的聯絡信箱是佔位值，**上線前務必換掉**
